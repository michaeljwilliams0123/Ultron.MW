# Triage labels

| Canonical role | GitHub label | Meaning |
| --- | --- | --- |
| needs-triage | `needs-triage` | Incoming, not yet assessed |
| needs-info | `needs-info` | Missing information or reproducible evidence |
| ready-for-agent | `ready-for-agent` | Bounded, testable and unblocked agent work |
| ready-for-human | `ready-for-human` | Requires owner decision, credentials, consent or manual action |
| wontfix | `wontfix` | Explicit disposition with rationale |

Use one primary triage-state label; existing priority, acceptance, governance and Council labels retain their independent meanings. Do not relabel all existing issues automatically. Triage raw incoming issues; tickets already produced from a verified spec do not repeat triage. State labels convey workflow readiness, never execution authority.
