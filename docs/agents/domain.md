# Domain documentation

Layout: **single-context**. Read root `CONTEXT.md` and the relevant source contracts first. Existing governance and acceptance documents remain canonical for their subject matter. Use `docs/adr/` for new decision records, linking the relevant issue, context, decision, alternatives, consequences, evidence and rollback.

Do not create competing glossaries, architecture authorities or databases. Record durable terminology in CONTEXT.md, not in transient chat summaries. Do not put private data in public docs. A proposed ADR has no operational authority.
