# Issue #525: independent source-inventory verification

Hatchable's authenticated get_deployment returns live status, version and per-file SHA-256 hashes but may omit source_sha. The alternative evidence path is an independently authenticated GitHub source inventory from the protected main Verify workflow. It proves current content equivalence to an exact Git commit, **not** historical deployment lineage or a provider assertion that the deploy command used that commit.

- The exact-main push attested-receipt job enumerates Git blobs from cloud/hatchable, excluding the existing non-runtime README and OPENAI-AGENTS-INTEGRATION documentation per the established parity contract. It produces a deterministic sorted SHA-256 inventory and signs the JSON using GitHub OIDC/Sigstore. The artifact name binds source SHA, inventory digest, count and run attempt.
- The runtime uses its existing authenticated GitHub OAuth proxy to independently read the canonical workflow's current exact-head successful run, successful inventory creation/sign/upload steps, and unexpired artifact metadata bound to that run and repository. It then rereads main. It does not download arbitrary artifacts, accept caller-supplied attestations, or claim to independently verify the Sigstore signature in the isolate; a separate release operator must verify the downloaded inventory using gh attestation verify with repository, signer workflow, source digest and source ref constraints.
- The runtime independently reads the live Hatchable manifest with the existing provider credential, requires the full provider digest and file count to match the receipt, and compares every application file's normalized inventory against the attested GitHub source inventory. Only the documented provider README exclusion is applied to content equivalence. README is still bound by the full provider artifact digest. Explicit conflicting provider SHA, unauthorized access, malformed inventory, stale run, missing or expired artifact, and any application content mismatch deny. No fallback from an explicitly wrong provider SHA.
- The original native provider-attributed source path remains supported. The signed owner grant, atomic receipt ledger, CI and trusted Council gate remain mandatory.
- Inventory artifacts retain for up to 90 days. Expiration is fail-closed; renew the evidence by rerunning the full protected exact-main verification workflow before expiration (or deploying a newly approved commit).

Acceptance sequence: merge through existing gates; verify the main workflow and download/cryptographically verify its source inventory; synchronize and deploy exact main; independently read provider version and digest; compare inventory; prepare and sign the exact scoped owner receipt; submit and reconcile; query release-proof and verify the sourceAttribution and attestor run/artifact identifiers. Do not close #525 on a local or mocked test result.
