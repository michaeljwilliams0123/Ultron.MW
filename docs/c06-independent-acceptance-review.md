# C06 independent acceptance review of model-generated candidate

## Provenance and scope
The three files `lib/c06-model-candidate.js`, `test/c06-model-generated.test.mjs`, and `docs/c06-model-generated.md` were generated by the owner-authorized, $0 GitHub Actions workflow [run 41775191071](https://github.com/michaeljwilliams0123/Ultron.MW/actions/runs/41775191071). The immutable, source-bound provenance is in `evidence/c06-model-origin.json`. **Do not modify or re-hash the model-origin artifacts without updating the evidence honestly.**

The additional `lib/c06-owner-safe.mjs` and `test/c06-independent-owner-boundary.test.mjs` were authored during independent review, **not** by the model. They protect the consumer boundary: authorization must be an explicit own data property, no inherited getters, no unknown operation fields, no spend other than literal zero, and no implicit authority from model output. The original model source remains unchanged.

## Independent behaviors checked
- Explicit active owner, zero spend, observed provider and independently verified receipt → deterministic `verified` classification.
- Unknown/timeout → `reconcile`; stopped/unauthorized/nonzero-spend/missing receipt → `held`.
- Prototype-inherited authorization, accessor traps, unsupported provider states and injected operation fields → `held` without calling an accessor.
- Generated vectors and these independent cases run through the protected exact-head Node and PostgreSQL acceptance workflow.

## What this does **not** prove
The model function evaluates a small deterministic owner-effect contract. It does not directly authorize or execute GitHub writes, create PRs, merge, pay Hugging Face, or deploy anything. A green generation/publish workflow is a **PR artifact**, not runtime production acceptance. Model-generated supporting documentation contains generic owner-application prose and is not an administrative access policy. The only trustworthy release policy remains the independently tested runtime authorization gates.

Issue #245 must remain open until an actual source-matched Hatchable deployment calls this model-origin code through the independent owner boundary, persists and independently verifies a real runtime consequence, and confirms protected merge and rollback evidence. The other protected acceptance issues are not automatically satisfied.
